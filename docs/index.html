Features

Remote desktop only — small and steady

Made for integration, not another bloated remote-control suite.

Windows built-in hardware encoding

Defaults to Media Foundation H.264: GPU hardware encoders first (Intel Quick Sync, NVIDIA…), built-in software as fallback. No codec library to ship.

FFmpeg is an optional extension

Need libx264rgb, H.265 or AV1? Unzip the extension next to FRD.exe. Without it those presets are clearly marked unavailable.

Frosted-glass floating panel

Direct2D blurs the live frame behind the panel. Drag it, fold it into an orb, latency always visible. The UI layer is open source as Glasspane.

Keyboard, mouse and clipboard

Input forwarding with cursor shape sync, plus two-way text, file and folder clipboard. On by default on the controller when available.

Shared annotations

Draw doodles, rectangles and text on the picture. The host sees them live on its own screen through a click-through overlay that screen capture ignores. Low priority by design: a separate connection, batched and rate-limited, so it costs video neither latency nor bandwidth.

Local input first

When someone is using the host's own keyboard or mouse, remote input is paused (releases still pass, so nothing sticks) and the controller shows “the other side is using the keyboard or mouse”. Only the injected flag and a timestamp are read, never key codes.

Progress and remote cursor

File copies show a progress bar on both sides (file n of m, percent, size). An optional overlay draws the host's pointer, position and shape, over the picture, even without input forwarding.

Reaches UAC and the lock screen

A separate frd-wintools.exe installs a SYSTEM helper once, enabling capture and input on the secure desktop. FRD never auto-clicks UAC.

Measurable latency

Capture, encode, transfer, decode and present are timed per stage, with GPU completion confirmed. A separate diagnostics stream measures cross-machine latency.

How it works

A short, honest pipeline

Video is sent at native resolution only (25 FPS by default; 10, 20, 25 or 30 on request); the window scales it. Bitrate cap, frame rate and codec preset can be changed live from the controller.

Quick start

Running in five minutes

Unzip the base package on both machines — nothing else to install. The host must be given an explicit listen address, port and token; there is no default token.

Host (a normal signed-in desktop)
PS> .\FRD.exe --host --listen 192.168.1.20 --port 5000 --token "our-secret"
Controller
PS> .\FRD.exe --connect 192.168.1.20 --port 5000 --token "our-secret"
Other commands
.\FRD.exe --version        # v4.pre3+<commit>
.\FRD.exe --help-window    # help window
.\FRD.exe                   # local demo (localhost)
.\FRD.exe --lang en|zh    # interface language (default: follows Windows)
Shortcuts
Ctrl+Alt        # leave input forwarding
Ctrl+Alt+F11    # toggle full screen
Ctrl+Alt+F12    # show/hide debug controls
Esc / Ctrl+Z    # annotation mode: leave / undo the last mark
Security: the token lives only for that launch — it is never saved or generated. --listen localhost is loopback only; :: binds every interface, so use it on trusted networks. Installing the secure-desktop helper needs administrator consent (UAC), which you confirm yourself.
Encryption is the underlay's job: FRD authenticates connections (the token is never sent; challenge-response with mutual proof) and signs keyboard/mouse datagrams, but it deliberately does not encrypt content. It is designed to run over an already-encrypted link such as a VPN, a tunnel or a private network, so it adds no packet size or latency of its own for the picture, clipboard and cursor.
