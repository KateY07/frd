# v1.pre5 静态审查与验证

日期：2026-09-18。审查范围：pre4 界面改动、原生输入消息、主控/被控退出路径；另检查传输缓冲上限、剪贴板路径与文件校验。不是所有平台和故障时序的无缺陷保证。

## 发现与修复

1. **P1：正常结束鼠标捕获会误释放修饰键。** `WM_LBUTTONUP` 后 `ReleaseCapture()` 产生 `WM_CAPTURECHANGED`，旧处理无条件发送 `ReleaseAll`。结果是物理 Ctrl/Shift 仍按住而远端已松开。改为仅在还有鼠标按键未释放时处理异常捕获丢失；失焦仍释放全部。隐藏窗口回归在 pre4 代码上明确失败，修复后通过。
2. **P2：正常停止监听存在误报致命错误的竞态。** 取消与 `TcpListener.Stop()` 并发时，接受连接可能收到对象已释放/监听未开始/操作中断异常。仅在停止令牌已取消时按正常结束处理，并保留日志；其他异常仍走失败路径。此项由静态控制流确认，不宣称已稳定复现竞态。
3. **P2：输入测试仍要求 Esc 退出。** 旧断言与 pre4 的 Ctrl+Alt 契约冲突。更新为当前快捷键规则，覆盖独立 Esc/F11 透传、组合键、按键重复及松开修饰键后释放 F11。
4. **P3：连接状态与诊断文案错误。** 成功连接后仍显示“正在连接”；诊断文案暗示编码滑条还约束诊断流量。分别补充成功状态和准确说明。

## 验证与边界

- 定向输入验证使用 localhost TCP 模拟注入器、隐藏的测试自有 HWND 消息及仅当前测试线程的按键状态，恢复线程按键状态；无 `SendInput`、真实指针移动或真实鼠标捕获。
- pre5 定向回归通过：输入消息 30 项、认证及失败退出/正常退出 38 项、IPv4/IPv6 双栈 10 项。结果位于本机 `results/release-v1.pre5/regression/`。
- pre5 真实桌面 UI 回归 Passed=true：接收 237 帧，GPU 确认 230 帧，Errors 为空；覆盖已连接状态、四种窗口尺寸、全屏恢复、面板/悬浮球位置、水印显隐与穿透。测试窗口已自动关闭。
- 主工程与重新生成的单文件 Demo 构建成功，零警告、零错误。
- pre4 发布后的后台回归已通过传输、实际编码码率、独立诊断、一秒统计、双向剪贴板协议。本次未改动这些后端，不将旧报告改标为 pre5；真实双机完整回归不包含在以上定向结果中。
- 自动键鼠注入继续暂停，UI 外观已由用户人工确认；不以软件测试替代物理屏幕延迟测量。

原生视频解码输出仍按帧分配 BGRA 数组，UDP 发送仍按包分配；这些是既有分配成本，本次没有基于静态观察宣称它们造成延迟，也没有在修复中引入池化生命周期风险。
