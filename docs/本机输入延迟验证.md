# 本机输入与画面反馈验证 · 2026-09-19

本轮优先独立针对性测试，Demo 只设计，尚未接入真实应用定向输入。下面的专用文本窗口是此前的测试夹具，不满足用户在预览中操作真实网页的体验需求；不能把其通过记录作为真实桌面操作已修复的证据。

本机主控与被控共享鼠标和键盘焦点，不能把双机的系统输入回注直接用于本机体验。此前工作树的 Demo 只把滚轮和键盘送到专用文本窗口；鼠标移动、点击、拖动在主控入口和接收目标两处拒绝。数据仍经过生产 TCP 输入协议，窗口变化仍经过真实捕获、FFmpeg、UDP、解码和 GPU 呈现。双机输入实现未改。

手动开启“本机滚轮 / 键盘”，点击预览后滚动、输入文字，Ctrl+Alt 退出。专用窗口支持基本字母、退格、方向键和翻页，不代表完整输入法、系统快捷键或真实 SendInput 到其他应用的行为。关闭 Demo 会一并关闭目标窗口。

## 输入协议排队

`RemoteInputClient` 在收到当前事件 ACK 前一直持有发送锁，UI 消费队列也逐个等待；两端已经开启 TCP_NODELAY。模拟回复方向的延迟，不改变真实系统鼠标。

| 条件 | 产生事件→模拟接收器：平均 / P95 / 最大 |
| --- | --- |
| localhost，无额外延迟，120 Hz 滚轮 | 1.00 / 1.92 / 4.02 ms |
| localhost，无额外延迟，60 Hz 键事件 | 0.49 / 0.75 / 1.47 ms |
| 实测 ACK 周期约 15.65 ms，120 Hz 滚轮 | 867.79 / 1659.85 / 1741.23 ms |
| 实测 ACK 周期约 31.32 ms，120 Hz 滚轮 | 2734.94 / 5214.97 / 5486.00 ms |

模拟请求的 5/10 ms 等待在本机 Windows 上实际约 15 ms，25 ms 实际约 30.5 ms，因此表中按实测 ACK 周期解释。测试使用模拟 FIFO，没有执行生产 UI 的坐标映射、移动合并和 512 事件上限；不能推广为移动鼠标的实测结果，也不是 LAN/RDP 的实测对比。

## 画面反馈

条件：已发布 pre6 被控端、回环连接、默认 `h264`（x264 veryfast）、1 Mbps 编码上限、原始 2880×1800、30 FPS 上限，无额外链路节流。专用窗口使用定向 WM_APP 消息变更带编号色块，测试预览排除屏幕捕获，避免递归；全链路采用本机 Stopwatch 时钟。

| 时间跨度 | 平均 | P95 | 最大 |
| --- | ---: | ---: | ---: |
| 消息发出→目标处理完成 | 0.64 ms | 0.88 ms | 1.63 ms |
| 消息发出→首次匹配画面解码 | 135.93 ms | 166.96 ms | 192.81 ms |
| 消息发出→匹配画面 GPU 完成 | 141.70 ms | 172.17 ms | 199.41 ms |

同期状态快照显示约 19 FPS，捕获约 12.5 ms、编码约 38.3 ms、传输约 1.1 ms、解码约 15.2 ms、呈现约 7.8 ms。这些是重叠的最近一秒窗口均值再取平均，只供定位，不能当作对应色块的精确逐层分解。面板从捕获开始计时，未包括输入到应用变化、DWM 更新以及捕获前的等待，因此不能代表操作响应时间。

此处记录首次基线：确认了输入 ACK 串行化风险，以及默认高分辨率软件编解码路径的可见反馈偏慢。没有测到真实 LAN 或同条件 RDP，不能声称二者差距已经量化。后续输入修复见本文末尾，原始报告保留。

可复现项目：`tests/InputLatency/`、`tests/InputVisualLatency/`、`tests/LocalInput/`。本机原始证据位于 `results/input-latency/`：`input-ack-baseline.json`、`visual-h264.json`、`local-directed-input.json`、`input-regression.json`、`demo-ui.json`。较早未排除预览的初探和被中止的 QSV 测试不计入结论。

## 竞品输入优先级调查

检查时间：2026-09-19。下面是源码事实，不代表已经实测其网络延迟。

- Sunshine/Moonlight：现代输入使用与视频分离的 ENet/UDP 控制流，可靠事件可以连续在途；普通输入不等待逐事件应用层回复。发送背压等待与远端 ACK 等待不同。[Moonlight 控制发送](https://github.com/moonlight-stream/moonlight-common-c/blob/master/src/ControlStream.c)、[输入队列及移动合并](https://github.com/moonlight-stream/moonlight-common-c/blob/master/src/InputStream.c)。
- Sunshine 控制连接启用 `ENET_SOCKOPT_QOS`；Moonlight 所用 ENet 的 Windows 实现实际以 `QOSTrafficTypeControl` 调用 QOS2，兼容不接受标记的路径时可退回无标记连接。[Sunshine 控制 Socket](https://github.com/LizardByte/Sunshine/blob/master/src/network.cpp#L207-L212)、[ENet Windows 实现](https://github.com/cgutman/enet/blob/aca87840b57f045a1f7f9299e4b1b9b8e2a5e2f1/win32.c#L483-L490)、[兼容回退](https://github.com/cgutman/enet/blob/aca87840b57f045a1f7f9299e4b1b9b8e2a5e2f1/protocol.c#L1728-L1732)。
- Windows 文档明确把用户输入列为最高优先级控制流的例子。标记是请求，路径设备仍需支持相应调度；任意自定义 DSCP 的 API 另有权限要求，不能把它与普通 QoS 流分类混为一谈。[控制流分类](https://learn.microsoft.com/en-us/windows/win32/api/qos2/ne-qos2-qos_traffic_type)、[QOSSetFlow 权限与失败条件](https://learn.microsoft.com/en-us/windows/win32/api/qos2/nf-qos2-qossetflow)。
- RustDesk：所查 TCP 路径写出输入后继续处理下一条，没有逐事件业务 ACK；服务端将注入交给输入线程。该会话的视频和其它消息虽分内存队列，仍写同一连接，不能宣称严格网络隔离或绝对输入优先。此次所查文件未找到 DSCP 设置，不推断整个项目都没有。[客户端发送](https://github.com/rustdesk/rustdesk/blob/ea04f04f9df2096fccba81a133c711166fe93b28/src/client/io_loop.rs#L643-L660)、[服务端网络循环](https://github.com/rustdesk/rustdesk/blob/ea04f04f9df2096fccba81a133c711166fe93b28/src/server/connection.rs#L1007-L1070)。

FRD 已有独立输入 TCP 连接、TCP_NODELAY 和连续移动合并；原先逐事件等待 ACK 已被上述模拟实验确认会在持续输入下积压。发送与确认分离的修复见本文末尾。网络 QoS 分类尚未接入，需继续测试空载、视频满载、双向文件传输下的输入排队、RTT、P95/P99 与可见反馈。不要因优先级而重排按下/释放，也不能把可靠键盘和按钮事件直接丢弃。

输入与视频主要方向相反，不能仅凭视频码率高就判定同一发送队列拥塞；Wi-Fi 共享空口、返回 ACK 及其它流量仍可能互相影响。[RFC 8325 对无线共享介质与 QoS 映射的说明](https://www.rfc-editor.org/rfc/rfc8325.html#section-1)。当前保留用户手动编码上限的语义，未额外加入链路限速或自动调整预设。

## 真实网页定向输入独立测试

测试工程 `tests/LocalDesktop/` 不属于正式程序。实验路由器也放在该目录，不会进入 FRD 或生成的单文件 Demo。测试打开独立 Edge 配置目录和自建网页，只操作该测试页，完成后关闭测试窗口。没有调用 SendInput、SetCursorPos 或更改全局键盘状态。

最近运行：`local-browser-background.json`，42 项检查通过，总计 8.80 秒（包括浏览器退出等待）。

| 路径 / 检查 | 实测结果 |
| --- | --- |
| 生产 TCP 输入协议 → 实验窗口消息路由 → 真实 Edge 网页 | 左、右、中键的按下/抬起抵达 DOM，左键触发按钮 |
| 键盘扫描码 → 页面文本框 | 恰好输入 `frd`，无重复字符；有完整按下/抬起 |
| 滚轮 → 网页 | scrollY 从 0 增至 300，不只验证消息发送成功 |
| 前台测试主控的生产 NativeInputSource → 异步发送队列 → TCP → 后台 Edge | 点击、再输入一次 `x`、再次滚动均通过；最终文本 `frdx`，scrollY 为 600 |
| 前台、键盘焦点、鼠标捕获 | 各观察点仍是测试主控前台及预览焦点；按下时持有捕获，抬起后释放；没有意外 ReleaseAll，最终无按键/按钮残留 |
| 系统鼠标 | 本次观察到位置未变；代码未移动它。此项只记录，用户同时移动鼠标不会被误判为失败 |

中键会启动 Chromium 原生自动滚屏，后续一次左键可能被浏览器消费以退出该模式。测试显式发送 Escape 退出后再测文本输入，保留这一真实浏览器行为；不能把它误判成 TCP 丢失鼠标按下。

该测试验证的是功能、消息顺序和焦点保持，不测延迟。网页每 100 ms 报告 DOM 状态，不能用报告到达时间推导输入延迟。它使用生产 NativeInputSource 和 TCP，但没有运行 Avalonia 完整预览、真实手动输入、输入法、系统快捷键、拖动或 Raw Input 应用；也没有将结果经视频回显。这些边界不能用“42 项通过”代替。

复现：

```powershell
dotnet build tests/LocalDesktop/LocalDesktopTests.csproj -c Release
.\tests\LocalDesktop\bin\Release\net10.0-windows\LocalDesktopTests.exe results/input-latency/local-browser-background.json --background
```

须运行带 DPI manifest 的 EXE，保证物理坐标与浏览器 CSS/devicePixelRatio 换算一致。

## 本机 Demo 方案草案（尚未接入）

目的：在预览中体验真实网页等应用，避免主控与被控争抢同一个系统鼠标。

1. 移动更新独立的虚拟指针；在预览上显示，不移动系统指针。需要悬停时向目标内容窗口发送定向移动消息。虚拟指针即时显示属于本地反馈，不能计为远端已响应。
2. 点击、滚轮和键盘仍走现有 TCP 输入连接。本机实验路由向预览坐标对应的真实内容窗口投递消息，按下与抬起绑定同一目标；最后点击的窗口接收后续键盘。保持主控焦点，不用临时搬动系统指针再恢复的方式制造抢夺。
3. 目标应用变化继续经过真实屏幕捕获、FFmpeg、UDP、解码和呈现。将虚拟指针反馈与应用画面反馈分开观察；测量操作到画面时，必须匹配实际画面变化。
4. 缩放、留边与 DPI 复用正式坐标变换，主控窗口和控制浮层排除为输入目标；退出、失焦、断线均释放仍按住的键/按钮。首轮只在已验证网页行为上开放体验，不宣称消息路由等价于系统输入。
5. 双机仍保留真实系统输入注入路径。IME、系统快捷键、窗口拖动、Raw Input 等要在双机或独立交互会话验证，不继续用消息模拟堆出一套完整输入系统。

优先级：先保留可复现的协议排队与画面反馈基线，再验证修复前后差异；Demo 接入后才做真实预览的缩放和回显测试。正式程序构建通过（零警告、零错误），没有发布新版本或重新打开 Demo。

## 输入流水修复与同条件复测

生产 `RemoteInputClient` 现在将顺序写入与单一后台 ACK 读取分开。新 `QueueAsync` 外层等待实际写入、内层返回真正的远端结果；既有 `SendAsync` 仍等真实结果，保持调用语义。UI 发送循环采用新路径并观察每个确认，最多 64 条在途；连续鼠标移动仍按原逻辑合并，按钮/按键顺序保留。5 秒无确认、取消已发请求、连接或协议错误均关闭连接，由服务端释放仍按住的键。关闭转发在写入前被取消或远端释放被拒绝时，也关闭连接，避免“本机已禁用，远端仍持键”。

| 同一延迟代理、120 Hz 滚轮 | 旧逐 ACK：平均 / P95 | 流水：平均 / P95 |
| --- | ---: | ---: |
| 仅回复方向配置 25 ms，实测 ACK 约 31.2 ms；生成→mock 注入 | 2727.28 / 5186.56 ms | 0.27 / 0.37 ms |

正向无附加延迟，以上不能解释为公网只需 0.27 ms。双向分别配置 25 ms 时，实测生成→mock 注入平均 31.54 / P95 34.57 ms、ACK 平均 62.89 ms，发送前排队 P95 0.18 ms；结果包含 Windows 调度影响。真实传播仍然存在，去掉的是每事件重复等待 ACK 导致的积压。

验证：18 个流水场景、16 个旧行为对照、32 项流水可靠性检查以及原有 30 项输入/隐藏窗口回归通过。可靠性含 64 条在途背压、取消、断线、错误序号、5 秒超时、迟到 enable 回复、disable 失败及重连；没有真实系统输入注入。报告为 `input-ack-pipeline.json`、`input-ack-serial.json`、`pipeline-disable-regression.json`、`input-regression-pipeline.json`。这不等于 RDP 对照、视频满载或最终画面延迟已经通过；共享瓶颈另见 `受限公网回归设计.md`。
