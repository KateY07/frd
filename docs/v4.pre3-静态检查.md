# FRD v4.pre3 静态检查

检查范围：多语言（`src/Support/Loc.cs`、`src/Support/LocEnglish.cs`）、所有界面和消息字符串、`--lang` 参数处理、布局回归。

- 版本：两个项目的信息版本均为 `v4.pre3`。
- 机制：源文本是中文，`Loc.T(中文)` / `Loc.F(中文格式, 参数…)` 在英文模式下按中文原文查表，查不到就原样返回中文，因此漏翻译不会出错。`Loc.Initialize` 在 `Main` 最开始读取并移除 `--lang X` / `--lang=X`，再读 `FRD_LANG`，最后用 `GetUserDefaultUILanguage()` 判断系统语言（NativeAOT 开启了 InvariantGlobalization，`CultureInfo` 无法区分）。
- 覆盖：扫描 `src/**/*.cs` 中全部含中日韩字符的字符串字面量（192 条，其中 34 条插值字符串），逐条改成 `Loc.T/F`；扫描复查后只剩一个与语言无关的省略号字符。`const` 字符串（`Usage`、一个局部常量）改成属性/变量。
- 翻译核对：192 条英文翻译与中文的 `{n}` 占位符集合逐条一致，大括号配平；`FormatException` 在两种语言的回环会话日志中为 0。
- 行为：状态点的颜色原先用中文前缀“正在”判断，改成判断是否以“…”结尾，与语言无关；其余关键词判断（“失败”“错误”等）有对应的英文关键词。
- 布局：`UiLayoutRegression` 在中文和英文各 40 种情况下检查重叠与越界，0 问题。
- 已知限制：被控端通过网络发来的状态文字（例如“安全桌面切换中…”）按被控端的语言显示，控制端不会再翻译；错误堆栈、日志和回归报告保持英文/原样。
- 未覆盖：目视检查英文界面的实际观感（由使用者确认）；系统语言检测在非中文系统上只验证了英文系统。
