# v1.pre1 开发验证

2026-09-18，Windows x64，Intel Core Ultra 9 285H / Intel Arc 140T，真实主屏 2880×1800，编码输出 1280×720，最高 30 FPS。以下是此次有限样本的观测，不是所有场景的延迟保证。

## 发送策略与码率

普通运行取消了按编码滑条再次发送限速；显式 JSON 容量模拟仍保留。

- 原严格 1 Mbps 网络模拟：6200 字节访问单元拆成 6 个 UDP 包，平均传输约 49.88 ms，其中计划等待约 47.31 ms。这是限速策略造成的等待。
- 新普通发送：同样 6200 字节真实 UDP 传输及重组，1 / 5 / 1 Mbps 编码设置各测 40 次，均值分别 0.134 / 0.124 / 0.129 ms，计划等待均为零。此测试没有捕获、编码、解码或渲染，不能用来证明端到端低于 1 ms。
- 独立编码回归：高变化合成像素，连续修改现有 H.264 编码器；每档 90 帧，以 30 FPS 媒体时间统计码量，不经过 UDP 或限速器。

| 设置 kbps | 实际编码 kbps |
|---:|---:|
| 1000 | 1009.68 |
| 2000 | 1941.01 |
| 3000 | 2778.91 |
| 4000 | 3684.04 |
| 5000 | 4616.45 |
| 1000 | 1005.31 |
| 500 | 506.36 |
| 5000 | 4585.05 |

全部符合“设置码率 × 媒体时长 + 100000 bit VBV 突发容量”，且全部解出 90 帧。短窗口稍高于设置值来自允许的 VBV 突发；这不是逐毫秒的链路硬限速。验证只存在于开发测试。

## 功能回归

- 远端协议 20 项通过：错误口令拒绝、独立输入连接、软件/QSV 预设切换、码率调整、不可用 AV2 拒绝、诊断开关、重新连接、独立计时器时间基转换。输入测试不向用户桌面注入真实按键。
- 两个独立进程实屏可视回归：收到 130 帧，123 帧 GPU 确认呈现；阶段相加、传输拆分及覆盖面板布局通过。捕获到 GPU 完成平均 13.25 ms，其中传输平均 0.37 ms。跨进程按跨机协议估计时钟；这不是两台物理机器的结果。
- 最终便携包 localhost 实屏回归：129 帧 GPU 确认呈现，平均 10.44 ms；捕获 3.20、编码 3.20、传输 0.46、解码 1.41、渲染 2.17 ms。包含启动样本、当时桌面变化和系统负载，未做受控滚动对比，也未测显示器扫描发光。
- 独立诊断包 9 项、键鼠协议/坐标/释放 26 项、最近一秒统计 3 项通过。
- 主项目及生成的单 C# 文件 Demo 编译零警告、零错误；便携包版本字段为 `v1.pre1`，无需另装 .NET。打包测试发现的 FFmpeg 外置加载问题已修复并复测。

## 本机编解码候选

同一份真实桌面像素，1280×720、1 Mbps，90 帧，排除前 10 帧；包括当前 CPU 转换及硬件路径上传/读回，不含 UDP 或渲染，不是等画质竞赛。

| 候选 | 编码均值 ms | 解码均值 ms | 结论 |
|---|---:|---:|---|
| H.264 veryfast 软件 | 2.86 | 1.25 | 默认可用 |
| H.264 ultrafast 软件 | 2.22 | 0.98 | 当前路径较快，预设 `h264_fast` |
| QSV H.264 + 软件解码 | 6.11 | 1.21 | 可用，预设 `h264_qsv_swdec` |
| QSV H.264 + D3D11 解码 | 5.68 | 4.05 | 可用；与上一行 QSV 参数略有差异 |

HEVC QSV 的强制关键帧配置及 AV1 QSV 探测存在失败，未据此加入可用预设。Media Foundation H.264 探测出现额外帧缓存，不列为更低延迟选择。硬件编解码不等于当前 CPU/GPU 往返路径一定更快。

## 尚未宣称完成的验收

真实双机、真实鼠标交互手感、各类动态内容的长期体验和 NVIDIA 实机验收仍待进行；本版本不宣称全部场景低于 1 ms，静止流量也不保证为零。此前一次硬解访问冲突未稳定复现，不能宣称彻底修复。跨机计时误差包含路径非对称等因素，界面展示的采样不确定度不包含后续时钟漂移。

复现命令与限制见 [使用说明](使用.md)；测试源码在 `tests/`。桌面像素、原始截图和机器专属日志不进入仓库。
