# GPU 缩放与灰度：回读前可行性短测

2026-09-20，本机 Intel Arc 140T、2880×1800 真实 DDA 桌面。DDA 本身固定输出 BGRA8；本测试在取得纹理后、CPU 回读前使用 D3D11 像素着色器缩放或写入 R8_UNORM 灰度纹理。每条路径取一幅真实桌面图，预热 5 次，再对保留的 GPU 图像重复转换和回读 30 次；不等待新的显示帧，也不含编码、UDP、解码或渲染。计时包含 `AcquireNextFrame(0)` 调用、GPU 提交、`Map` 等待和拷入 CPU 输出缓冲区。原始结果见 `results/gpu-prereadback.json`。

| 回读前 GPU 输出 | 原始数据 | 平均 | P95 | Map 等待均值 | CPU 拷贝均值 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 原尺寸 BGRA8，像素着色器对照 | 20.74 MB | 6.01 ms | 8.11 ms | 2.22 ms | 3.50 ms |
| 宽高各半 BGRA8 | 5.18 MB | 1.97 ms | 2.95 ms | 1.15 ms | 0.71 ms |
| 原尺寸 Gray8 | 5.18 MB | 2.25 ms | 3.36 ms | 1.38 ms | 0.74 ms |
| 宽高各半 Gray8 | 1.30 MB | 1.28 ms | 2.03 ms | 0.94 ms | 0.27 ms |

四条路径均输出正确长度、非单色的字节数据；本轮只完成基本有效性检查，没有建立同一源帧逐像素画质证明。按“平均和 P95 均低于 10 ms”的筛选线，四条都可行。`GpuScaleSubmitMs` 只是 CPU 提交时间；GPU 完成等待计入 `Map`，不能把约 0.01 ms 的提交值当成完整变换耗时。

**边界：**6.01 ms 的全尺寸像素着色器路径不是当前最快的生产基线。此前原尺寸 DDA 直接映射路径的 staging 映射约 2.22 ms，且 `libx264rgb` 可借用其 BGRA 内存。Gray8 路径要真正提速，还须让编码器直接接受单通道输入，并完成画质与完整码流验证；若重新扩成 BGRA，减少回读的价值会被抵消。宽高各半会损失空间细节，应是显式选择，不替换当前原尺寸模式。超过 10 ms 即停止该候选的规则在本次没有触发，但低于 10 ms 也不等于完整链路已获益。
