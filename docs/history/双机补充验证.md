# v1.pre1 后续双机验证

2026-09-18，用户提供另一台 RTX 5070 Ti 机器。通过已有运维通道的 JSON `stdin` 分块传送 189012029 字节 ZIP，逐块及整包 SHA-256 校验一致后解压；上传约 18.8 秒，含整包校验与解压约 24.2 秒。未通过额外服务传包，临时 HTTP 服务已关闭，未成功创建任何防火墙规则。后续修复包也通过同一运维通道部署。

## 环境与修复

被控端为 RTX 5070 Ti、真实 2560×1440 桌面；主控为 Intel Arc 140T。本次由被控端捕获并 NVENC 编码，主控软件解码、GPU 呈现；输出 1280×720，最高 30 FPS，直连以太网真实 UDP，不启用模拟链路限速。

首次控制连接成功但主控收不到视频。让视频与诊断接收端口分别主动向已认证的发送端发一个 8 字节登记包后，UDP 返回通路恢复。登记包不属于视频数据，不改变原视频格式。关闭很久后重新开启诊断也会再次登记。

真实 NVENC 测试暴露默认输出缓存：仅 `-zerolatency 1` 仍有约两帧输出延后。预设补上 `-delay 0`；同时增加 `-forced-idr 1`，使恢复请求产生 IDR。保留原 CUDA 解码预设，另提供 `*_nvenc_swdec` 供不同厂商的主控使用。

也修复了远端可视回归失败后进程仍返回零的问题；判断结果始终同时检查报告，首次零帧测试没有被当成通过。

## 结果

- 真实双机控制回归 32 项通过：错误口令拒绝、连接与重连、H.264 NVENC 的 1/2/3/4/5/0.5 Mbps 切换、AV1/HEVC NVENC 切换、软件预设切换、不可用 AV2 拒绝、诊断开关、输入通道启停及独立时钟换算。
- 真实可视回归收到 252 帧，246 帧 GPU 确认呈现，无报告错误。整个短测试捕获到 GPU 完成平均 **10.19 ms**；最后一秒平均 **8.82 ms**。捕获、编码、传输、解码、呈现的整个测试均值分别为 **1.76 / 3.32 / 0.74 / 1.52 / 2.85 ms**。计划发送限速等待为零。
- 时间是跨机时钟估算：末次采样不确定度约 ±0.21 ms，不包含后续时钟漂移；不是显示器扫描发光延迟，也不是所有动态场景的保证。
- UDP 登记新增两个回归，连同原独立诊断、格式和显式限速模拟共 11 项通过。使用既有真实视频与独立诊断通道，未借运维通道运送视频。

本次控制测试的输入只检查启停与应答，不冒充真实键鼠交互体验验收；该体验留在可视双机 Demo 中供人工确认。本次没有系统穷举网页滚动、局部视频及丢包条件，也未据此宣称平均低于 1 ms 的原目标全面达成。

首次 `v1.pre1` 标签保持不变；这些双机修复作为后续提交进入 `main`。实际部署包的版本仍属于 v1.pre1，提交号用于区分修复前后。
