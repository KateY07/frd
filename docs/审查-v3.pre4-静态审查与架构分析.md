## 3. 静态扫描结果

- **编译**：主程序、辅助服务、Glasspane 均 0 错误；3 条警告：`MfEncoder.cs:57` 字段 `pendingOutputs` 未使用；`UiControllerWindow.cs:89` 可能的空引用；Glasspane `UiPanel.cs:22` 字段 `pressedOnBackground` 只写不读。
- **异常处理**：12 处空 `catch`。其中 `MfEncoder/MfDecoder` 的 7 处是对可选 MFT 属性和结束流消息的容错（有意为之）；`FfmpegShutdown` 的 2 处是强制退出前的最后一搏；`FfmpegSecureHelper` 的 2 处是清理/读取安装错误文件。未发现吞掉关键业务错误的空 `catch`，但数十处 `catch (Exception)` 分布在十几个文件，建议逐步收窄。
- **同步阻塞**：15 处 `GetAwaiter().GetResult()`/`Wait`。多数在 `Main`、回归测试和停止流程里；`FfmpegTransport.cs:719` 在专用线程上阻塞读取通道，`FfmpegSecureDesktop.cs:237` 在线程退出时等待读取任务，均可接受。`FfmpegApp.cs:698` 在 `Dispose` 中同步等待 `StopAsync`，在 UI 线程调用会有死锁风险；本版关闭流程已有超时与强制退出兜底。
- **不安全代码**：`unsafe`/`stackalloc`/`fixed` 集中在 FFmpeg 绑定（`FfmpegBackend`）、BGRA↔NV12 转换（`MfColor`）、共享内存（`FfmpegSecureShared`）和 vtable 调用（`MfInterop`），边界检查在调用方完成；未发现明显越界。
- **输入校验（做得好的部分）**：
  - 剪贴板文件/目录接收（`FfmpegClipboard.cs:388–401`）拒绝绝对路径、反斜杠、`..`、保留设备名和尾部点/空格，并在合并后再次检查路径包含关系；有 4 MB 文本、10,000 条目、2 GB 单文件上限。
  - 控制消息有 64 KB（回复 2 MB）长度上限和 10 秒握手超时；视频帧有 40 MB 上限与 80 MB 缓冲上限；输入消息 4 KB。
  - 口令比较和所有 HMAC/会话号比较使用 `CryptographicOperations.FixedTimeEquals`；通道只接受与当前会话、控制端地址匹配的连接，光标/剪贴板通道各限一条。
  - 被控端拒绝把输入注入到本地控制器/覆盖窗口，避免“控制自己”。
- **序列化**：协议类型使用 JSON 源生成上下文（AOT 安全）；报告用手写 `ReportJson`。`init` 属性在 .NET 10 源生成下不执行默认值的问题已改为 `set`（有静态检查记录）。
- **日志**：`SessionTrace` 只写通道名/状态/异常类型与堆栈，不含口令；但 `CrashLog` 写了完整命令行（见第 1 节）。两类日志都不会自动清理。

## 4. 架构分析

### 4.1 分层

```
                      ┌─────────────── FRD.exe（NativeAOT 单文件）───────────────┐
 命令行 ──▶ Program.Main (FfmpegApp.cs) ──▶ RemoteLaunch / DemoSession
                      │
   UI    UiApp ─ UiControllerWindow / UiHostWindow ─ UiControlPanel ──▶ Glasspane（Direct3D11/Direct2D 库）
                      │
   会话  RemoteSession（主控客户端） · RemoteHostServer（被控服务端） · 控制协议(JSON/TCP)
                      │
   通道  视频(UDP)  键鼠(UDP+TCP握手)  剪贴板(TCP)  光标(TCP)  诊断(UDP)
                      │
   媒体  捕获 FfmpegCapture/DesktopSource(DXGI→GDI)  →  编码 VideoEncoder ─┬─ MfEncoder（Media Foundation，默认）
                                                         解码 VideoDecoder ─┴─ FfmpegBackend（FFmpeg.AutoGen，可选，运行时加载）
                      │
   安全桌面  FfmpegSecure*（共享内存+回环UDP+HMAC）  ◀─ SYSTEM 服务 ─ frd-wintools.exe（独立 AOT 小程序）
```

### 4.2 做得好的地方

- **可选依赖隔离干净**：`VideoEncoder/VideoDecoder` 门面在 Media Foundation 与 FFmpeg 之间选择；FFmpeg 库懒加载、不可用时预设标记为不可用，退出码 2。基础包因此只有约 6 MB。
- **权限最小化**：只有辅助服务以 SYSTEM 运行，且被拆成独立 exe，主程序不含 SYSTEM 代码；安装需用户亲自点 UAC，FRD 从不自动批准。
- **会话模型清晰**：一个被控会话、控制端地址固定、各辅助通道必须携带会话号并与已有会话绑定；`ShutdownGuard` 与超时保证网络卡死时仍可退出。
- **UI 与业务已分层**：绘制/窗口/控件在 Glasspane 里，不依赖业务类型；FRD 的窗口只负责绑定。
- **可观测性**：分层计时、GPU 完成确认、独立诊断包。

### 4.3 结构性问题

1. **命名与职责漂移**：默认路径已是 Media Foundation，但 33 个文件仍叫 `Ffmpeg*.cs`，`Program.Main` 和 `AppConfiguration` 在 `FfmpegApp.cs` 里。新贡献者很难按文件名定位。建议改为 `Capture/`、`Codec/`、`Transport/`、`Session/`、`Channels/`、`Secure/`、`Ui/` 目录与对应命名空间。
2. **三个大文件职责混杂**：`FfmpegRemote.cs` 同时含启动参数、被控服务端、主控客户端和三个辅助通道客户端；`UiControllerWindow.cs` 把窗口消息、编码设置应用、键鼠/剪贴板开关、回归报告写在一起；`FfmpegApp.cs` 含配置、演示会话、控制协议和入口。可按“会话/通道/界面”拆开，改动面小、风险低。
3. **回归/基准代码随产品发布**：`--codec-regression` 等 10 余个开关及约 1,000 行回归代码编进了 `FRD.exe`。优点是单文件即可现场自检；缺点是命令面变大、体积增加。可考虑用条件编译或独立的 `FRD.Tools`。
4. **全局静态状态**：`SessionTrace`、`CrashLog`、`FfmpegRuntime`、`MediaFoundationRuntime`、`RemoteLaunch.hostExitCode`、`UiControllerWindow.RegressionExitCode`。对单进程单会话足够，但妨碍在同一进程内跑多会话测试。
5. **协议演进**：TCP 控制消息是长度前缀 JSON，输入协议版本号在握手里硬编码（`InputProtocol: 2`）；UDP 报文头有魔数但没有统一的版本协商。后续改协议需要“主被控同时升级”。
6. **配置**：`codec-config.json` 的预设参数使用 FFmpeg 风格字符串（`-c:v mf-h264 -rc cbr …`），由两套后端各自解析；缺少统一的 schema 校验，错误只在运行时暴露。
7. **多语言**：界面与错误信息硬编码中文，没有资源文件；主页与 Glasspane 为英文。若面向海外用户需要引入本地化。

### 4.4 威胁模型（简版）

| 攻击者 | 能做什么 | 现有防护 | 缺口 |
|---|---|---|---|
| 同网段被动嗅探 | 读到口令、会话号、屏幕内容、剪贴板 | 无 | **无传输加密** |
| 同网段主动攻击 | 用嗅探到的会话号向 UDP 输入端口注入键鼠 | 会话号随机 16 字节；控制端地址绑定 | 地址可伪造/同 NAT；无报文认证 |
| 任意网络用户 | 猜口令 | 常量时间比较、10 秒超时 | **无失败限速/锁定** |
| 本机普通用户 | 读 FRD 日志取口令 | 日志在用户自己的目录 | 同用户进程本就能读命令行；多用户机器上风险有限 |
| 本机普通用户 | 替换 SYSTEM 服务的可执行文件 | 无 | **服务路径未校验/未固定到管理员可写目录** |
| 本机其他进程 | 抢占回环端口 59873/59874 造成拒绝服务 | HMAC 防伪造 | 无法防占用 |

## 5. 建议（按投入/收益排序）

1. **修提权风险（高）**：安装服务时把 `frd-wintools.exe` 复制到 `%ProgramFiles%\FRD\`（仅管理员可写），服务指向该副本，安装前校验源文件哈希；升级时同样覆盖。工作量小。
2. **日志脱敏（高）**：`CrashLog` 不再写 `Environment.CommandLine`，改为写去掉 `--token` 值的版本；同时给日志加保留策略（如只保留最近 20 个）。工作量极小。
3. **传输安全（高，较大）**：最低成本方案是在 TCP 握手后用口令派生密钥（例如 PAKE 或口令加盐的 HKDF）协商会话密钥，对 UDP 报文做 AEAD（AES-GCM/ChaCha20-Poly1305）和序号防重放；或明确要求在 VPN/受信网络内使用，并在 UI/文档中写明“未加密”。
4. **口令限速（中）**：按来源地址对失败次数做指数退避，并限制未认证连接数。
5. **清理测试资产（中）**：把已编译不过的 9 个测试工程（`LocalDesktop`、`DesktopProbe`、`SecureDesktopProbe`、`LocalInput`、`InputPipeline`、`Input`、`ConstrainedNetwork`、`InputVisualLatency`、`PathSwitchResilience`）修复或移入 `archive`；停用或重生成 `demo/FrdDemo.cs`；把能跑的测试接入一条本机脚本。
6. **目录与命名整理（低）**：按第 4.3 节重命名并拆分三个大文件，不改变行为，可借助现有回归保护。
7. **收窄 `catch (Exception)`、消除 3 条警告（低）**。
