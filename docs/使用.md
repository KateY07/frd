# FRD v1.pre5

Windows x64 桌面原型。CLI 入门见根目录 README，目标见 docs/目标与验收.md；本文记录运行和构建方法。

## 运行

完整便携目录包含 `FRD.exe`、`codec-config.json` 和 `ffmpeg/`。双击启动 localhost 实屏演示；窗口可缩放，画面保持比例。窗口采用 Avalonia Simple 主题，紧凑控制栏覆盖于画面之上。

推荐无管理员权限的安装目录：`%LOCALAPPDATA%\Programs\FRD\v1.pre5\`。不同版本分目录保留，完整便携包包含 README 与说明文档；不用放入 `Program Files`，无需写注册表或系统服务。本版保留人工确认的 pre4 界面，修复内容见版本说明。

两台机器使用同一套文件；在普通已登录桌面中启动：

```powershell
# 被控端：真实捕获、编码，监听用户指定 TCP 端口
.\FRD.exe --host --listen 192.168.1.20 --port 5000 --token "双方相同的自定口令"

# 主控端：替换为被控端 IPv4/IPv6 地址
.\FRD.exe --connect 192.168.1.20 --port 5000 --token "双方相同的自定口令"
```

控制与独立键鼠连接共用被控 TCP 端口，视频、诊断及反馈使用协商的 UDP 端口；两端需允许 FRD 通过所在局域网防火墙。当前支持 IPv4/IPv6 双栈、单主控连接，不提供 NAT 穿透。口令用于连接认证，通道尚未加密，适用于可信局域网或已有加密隧道。

`--listen`、`--port`、非空 `--token` 每次启动被控端均必填。`--listen localhost` 仅接受两种本机回环；`--listen ::` 使用单 IPv6 双栈 Socket 接受 IPv4/IPv6；`::1` 仅限 IPv6 回环。不可恢复异常向 stderr 输出原因并以退出码 1 退出。

主控手动启用键鼠转发，Ctrl+Alt 退出转发，断开释放按键。Ctrl+Alt+F11 或控制栏全屏按钮切换全屏；启用转发时，单独按 Esc 或 F11 仍传给远端。主控不会捕获自己的桌面。原 localhost 模式有防止输入回注预览窗口的保护，不能代替双机输入体验验收。

控制栏展开时，按住空白区域即可拖动；按钮、下拉框和滑条仍按各自功能操作，不会触发面板拖动。收起后，画面上保留 50 像素半透明悬浮球；按住拖动可调整位置，单击恢复控制栏。两种状态的拖动范围均限制在视口内，窗口缩放或切换全屏时保留当前位置，必要时调整至可见范围。

传输比例默认为 `1×` 源桌面原始宽高，控制栏可切换 `0.75×`、`0.5×`，由被控端重新配置捕获与编码；格式需要时向下对齐偶数像素。拉伸主控窗口只改变等比例显示，不改变传输分辨率。JSON 的 `transmissionScale` 指定初值；`width` / `height` 保留给独立编码基准测试。

键鼠转发开启时，预览区域使用远端的鼠标形状、热点与显隐状态；移出画面或退出控制后使用本机指针。鼠标移动仍由本机即时显示，远端形状通过独立连接更新，不等待视频。支持 Windows 彩色及单色 AND/XOR 掩码指针，缓存最多 64 种形状；当前按形状快照同步，不承诺完整重现动画指针的每一帧。观察模式暂不叠加对端鼠标位置。

## 双向剪贴板

在主控控制栏勾选“剪贴板同步”，之后新复制的文本、普通文件和目录可双向同步；开启前已有内容不会自动发送。取消勾选或断开即停止同步。

文件先接收到 `%LOCALAPPDATA%/FRD/Clipboard/` 下的独立暂存目录，全部接收并通过 SHA-256 校验后，才写入本机 Windows 文件剪贴板。随后在资源管理器按 Ctrl+V，复制进度、目录合并和同名替换由 Windows 处理。传输过程中显示接收状态，尚未完成的数据不会变为可粘贴文件；本机出现新复制内容时，旧的未完成传输不会覆盖它。

同名顶层文件分别暂存，保持原文件名及目录结构，包括空目录。当前上限为单次文本 4 MiB、128 个顶层项目、10000 个文件/目录、文件合计 2 GiB；缓存总量上限 4 GiB。为保证粘贴后仍可重试，已完成的暂存文件会保留，粘贴完成后可清理该缓存目录。链接、目录联接及邮件附件等虚拟文件暂不支持；文件采用复制语义，不删除源文件。

## 控制与统计

- 码率仅通过滑条调整，当前数值在标签中以 Mbps 显示，默认范围 0.1–100 Mbps；上限来自被控端 JSON 的 `maximumBitrateMbps`，可设为 0.1–1000，连接时同步给主控。该控件只限制编码码率。编码帧产出后即时 UDP 发送，允许突发；不存在对应的发送限速。VBV 允许短时码量超过均值，瞬时发送带宽也不等于编码上限。
- 主控选择预设后，通过控制连接应用到被控端；带宽参考值不替用户选预设或改码率。参考值基于实际流量，低负载时只是容量下界。
- 编码器不支持原地修改参数时，准备替代编码器并切换代次。无效预设会报错，保留有效流。新编码预设由被控端 JSON 定义；两端都必须有相应编解码库与硬件。
- 显示捕获、编码、传输、解码、渲染及最近一秒平均值。渲染完成指 GPU 事件确认，未测显示器扫描发光。跨机时间为带时钟采样不确定度的估算，不能据此验证亚毫秒物理单向延迟。
- 诊断由主控开关，走独立 UDP 包，不改变视频头或阻塞视频。关闭跨机诊断后不再显示捕获到渲染总耗时。
- 诊断信息位于画面底部的半透明水印，不拦截鼠标、不获取键盘焦点；控制栏可独立隐藏水印。水印显隐与诊断包开关独立：隐藏只改变显示，不关闭诊断采集或网络诊断包。上方控制栏独立可折叠，操作控件仍可正常点击。
- 静止画面可由帧间编码逐步改善；重复解码帧不一定需要再次渲染。实际呈现 FPS 可接近零，但编码与协议流量不保证为零，定期关键帧也不是无损清晰度保证。

## JSON

编辑可执行程序旁的 `codec-config.json`，重启加载定义；会话内可切换已加载预设。示例全集见 `codec-config.example.json`。

```json
{
  "label": "H.264 / 软件",
  "encoderArguments": "-c:v libx264 -preset veryfast -tune zerolatency -crf 20 -bf 0 -g 300 -threads 4 -bufsize 100k",
  "decoderArguments": "-c:v h264 -threads 1"
}
```

参数采用 FFmpeg 风格的单行字符串，经适配器映射到 libavcodec，并非启动任意 FFmpeg 命令行；不支持输入设备、滤镜图、封装器等完整 CLI 功能。未知参数明确报错。`{bitrateKbps}` 可引用当前滑条值；显式 `-maxrate` 与滑条取较低上限。

已有 H.264、VP9、AV1、QSV、NVENC/NVDEC 预设。实际支持取决于两端硬件；已追加 RTX 5070 Ti 编码到 Intel 主控软件解码的实机验证。不同厂商的两端可选择 `h264_nvenc_swdec`、`av1_nvenc_swdec`、`hevc_nvenc_swdec`；原 `*_nvenc` 预设仍使用 CUDA 解码，需要主控也有 NVIDIA。NVENC 预设显式设置 `-delay 0 -forced-idr 1`，避免额外输出帧缓存并允许请求独立恢复帧。AV2 在当前构建中不可用，明确禁用。

`simulation.capacityMbps: 0` 表示不模拟容量限制；`lossRate: 0`、`maxDelayMs: 0` 关闭额外丢包与延迟。仅专项测试显式设置非零值，UI 会显示容量模拟状态。

## 构建

需要 Windows x64、.NET 10 SDK 和 7-Zip。根目录执行：

```powershell
.\Get-FFmpeg.ps1
dotnet build FRD.csproj -c Release -o bin/live-demo
.\Build-SingleFileDemo.ps1
dotnet build demo/FrdDemo.csproj -c Release
.\Publish.ps1
```

`demo/FrdDemo.cs` 是从生产源码生成的单 C# 文件 Avalonia Demo，勿单独修改它。发布脚本的输出目录为 `artifacts/v1.pre5/win-x64`，便携包为 `artifacts/v1.pre5/frd-v1.pre5-win-x64.zip`，同目录生成 `SHA256SUMS.txt`。托管程序及 .NET 运行时打包进同一个控制台 EXE，FFmpeg 库和可编辑 JSON 留在旁边。复制整个目录到另一台 Windows x64 机器，无需另装 .NET。在终端直接调用时持续阻塞，直到窗口关闭、资源清理完成并返回退出码。发布脚本从新目录构建；替换的旧构建移入 `archive/replaced-builds/`。发布后回归发现问题时，修复后发布新的 pre 版本，不移动旧版本标签。

## 开发回归

```powershell
dotnet run --project tests/Core -c Release -- --transport results/core
dotnet run --project tests/Core -c Release -- --codec results/core bin/live-demo/codec-config.json
dotnet run --project tests/Diagnostics -c Release
dotnet run --project tests/Input -c Release -- results/input.json
dotnet run --project tests/Stats -c Release -- results/stats.json
dotnet build tests/Remote -c Release
.\tests/Run-Remote.ps1
# 新增交互功能短测（测试窗口自动关闭，原剪贴板恢复）
dotnet build tests/Interaction -c Release -o bin/interaction-tests
.\bin/interaction-tests/InteractionTests.exe results/interaction/protocol.json
.\bin/interaction-tests/InteractionTests.exe --clipboard results/interaction/native-clipboard.json
.\tests/Run-Interaction.ps1
# 有 Intel QSV 的测试机可以追加 -Qsv
```

远端回归启动两个独立进程并自动关闭测试窗口；软件路径为默认，硬件测试显式开启。核心编码回归使用高变化合成像素独立检查码量，远端和可视回归使用真实桌面。开发测试验证码率控制，生产不增加额外校验反馈环。

真实双机回归可给 `tests/Remote` 设置 `FRD_TEST_HOST`、`FRD_TEST_PORT`、`FRD_TEST_TOKEN` 环境变量，并追加 `--nvenc`。不要把实际令牌提交到仓库。主控从视频和诊断接收端口向已认证的发送地址各发 8 字节 UDP 登记包，打开有状态返回通路；不修改防火墙，不改变视频包结构，也不改用 TCP 传视频。
