# FRD v1.pre1

Windows x64 桌面原型。目标见根目录唯一的 README；本文只记录运行和构建方法。

## 运行

完整便携目录包含 `FRD.exe`、`codec-config.json` 和 `ffmpeg/`。双击启动 localhost 实屏演示；窗口可缩放，画面保持比例。控制面板覆盖于画面之上并可折叠。

两台机器使用同一套文件；在普通已登录桌面中启动：

```powershell
# 被控端：真实捕获、编码，监听用户指定 TCP 端口
.\FRD.exe --host --port 5000 --token "双方相同的自定口令"

# 主控端：替换为被控端 IPv4 地址
.\FRD.exe --connect 192.168.1.20 --port 5000 --token "双方相同的自定口令"
```

控制与独立键鼠连接共用被控 TCP 端口，视频、诊断及反馈使用协商的 UDP 端口；两端需允许 FRD 通过所在局域网防火墙。当前实现为 IPv4 单主控连接，不提供 NAT 穿透。口令用于连接认证，通道尚未加密，适用于可信局域网或已有加密隧道。

主控手动启用键鼠转发，Esc 退出控制，断开释放按键。主控不会捕获自己的桌面。原 localhost 模式有防止输入回注预览窗口的保护，不能代替双机输入体验验收。

## 控制与统计

- 滑条范围 100–5000 kbps，只限制编码码率。编码帧产出后即时 UDP 发送，允许突发；不存在对应的发送限速。VBV 允许短时码量超过均值，瞬时发送带宽也不等于编码上限。
- 主控选择预设后，通过控制连接应用到被控端；带宽参考值不替用户选预设或改码率。参考值基于实际流量，低负载时只是容量下界。
- 编码器不支持原地修改参数时，准备替代编码器并切换代次。无效预设会报错，保留有效流。新编码预设由被控端 JSON 定义；两端都必须有相应编解码库与硬件。
- 显示捕获、编码、传输、解码、渲染及最近一秒平均值。渲染完成指 GPU 事件确认，未测显示器扫描发光。跨机时间为带时钟采样不确定度的估算，不能据此验证亚毫秒物理单向延迟。
- 诊断由主控开关，走独立 UDP 包，不改变视频头或阻塞视频。关闭跨机诊断后不再显示捕获到渲染总耗时。
- 静止画面可由帧间编码逐步改善；重复解码帧不一定需要再次渲染。实际呈现 FPS 可接近零，但编码与协议流量不保证为零，定期关键帧也不是无损清晰度保证。

## JSON

编辑可执行程序旁的 `codec-config.json`，重启加载定义；会话内可切换已加载预设。示例全集见 `codec-config.example.json`。

```json
{
  "label": "H.264 / 软件",
  "encoderArguments": "-c:v libx264 -preset veryfast -tune zerolatency -crf 20 -bf 0 -g 300 -threads 4 -bufsize 100k",
  "decoderArguments": "-c:v h264 -threads 1"
}
```

参数采用 FFmpeg 风格的单行字符串，经适配器映射到 libavcodec，并非启动任意 FFmpeg 命令行；不支持输入设备、滤镜图、封装器等完整 CLI 功能。未知参数明确报错。`{bitrateKbps}` 可引用当前滑条值；显式 `-maxrate` 与滑条取较低上限。

已有 H.264、VP9、AV1、QSV、NVENC/NVDEC 预设。实际支持取决于 FFmpeg 构建和本机硬件；本次机器没有 NVIDIA，未验收 NVIDIA 运行效果。AV2 在当前构建中不可用，明确禁用。

`simulation.capacityMbps: 0` 表示不模拟容量限制；`lossRate: 0`、`maxDelayMs: 0` 关闭额外丢包与延迟。仅专项测试显式设置非零值，UI 会显示容量模拟状态。

## 构建

需要 Windows x64、.NET 10 SDK 和 7-Zip。根目录执行：

```powershell
.\Get-FFmpeg.ps1
dotnet build FRD.csproj -c Release -o bin/live-demo
.\Build-SingleFileDemo.ps1
dotnet build demo/FrdDemo.csproj -c Release
.\Publish.ps1
```

`demo/FrdDemo.cs` 是从生产源码生成的单 C# 文件 Avalonia Demo，勿单独修改它。发布产物位于 `artifacts/v1.pre1/win-x64`：托管程序及 .NET 运行时打包进同一个 EXE，FFmpeg 库和可编辑 JSON 留在旁边。复制整个目录到另一台 Windows x64 机器，无需另装 .NET。

## 开发回归

```powershell
dotnet run --project tests/Core -c Release -- --transport results/core
dotnet run --project tests/Core -c Release -- --codec results/core bin/live-demo/codec-config.json
dotnet run --project tests/Diagnostics -c Release
dotnet run --project tests/Input -c Release -- results/input.json
dotnet run --project tests/Stats -c Release -- results/stats.json
dotnet build tests/Remote -c Release
.\tests/Run-Remote.ps1
# 有 Intel QSV 的测试机可以追加 -Qsv
```

远端回归启动两个独立进程并自动关闭测试窗口；软件路径为默认，硬件测试显式开启。核心编码回归使用高变化合成像素独立检查码量，远端和可视回归使用真实桌面。开发测试验证码率控制，生产不增加额外校验反馈环。
