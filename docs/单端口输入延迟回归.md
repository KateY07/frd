# 单端口输入延迟：定位与闭环验收

2026-09-22，随 v2.pre3 发布的修复与测试。

## 验收口径

最终指标为主控产生移动事件，到被控端 Windows 鼠标实际到位，再到这一变化返回主控并完成显示。不能以 UDP 发包成功、ACK 或被控端输入执行完成代替这一指标。

自动测试的可观测终点为匹配帧的 D3D11 GPU 完成，不包括显示器扫描输出及物理鼠标采样延迟。鼠标位置引起的应用画面响应，与本地预测绘制的光标应分别评价。

## 已确认的问题及修复

被控端公共 UDP 收包循环同步处理反馈，反馈处理等待 `UdpVideoSender.statsGate`，与视频统计共享锁。此时输入包无法及时被读取。

修复把反馈处理移到独立工作线程，以单槽保存最新累计反馈，避免反馈本身积压；UDP 收包使用独立线程，输入执行继续独立。外部端口、UDP 包格式和来源校验不变。内部输入测时通过可选观察回调获取接收、执行开始和结束时间，不增加跨机诊断负载，观察回调故障不终止会话。

## 已完成的内部对照

`dotnet run --project tests/PathSwitchResilience -c Release -- --input-load results/input-load-after.json`

使用真实生产单端口 UDP 发送、接收、反馈及输入分流；视频为合成帧载荷，注入器为 mock。不是实际鼠标跟随验收，也没有模拟公网瓶颈。

| 视频负载 Mbps | 修复前平均/P99 ms | 修复后平均/P99 ms |
| --- | --- | --- |
| 0 | 0.186 / 0.328 | 0.168 / 0.414 |
| 5 | 0.158 / 0.332 | 0.158 / 0.301 |
| 20 | 0.148 / 0.268 | 0.155 / 0.294 |
| 60 | 0.165 / 0.336 | 0.157 / 0.491 |

每组 250 个输入样本。常规负载未复现明显延迟增长，不能据此断言用户观察到的卡顿全部源于统计锁。

定向持有真实统计锁 180 ms：修复前只执行并观测到 7/15 次移动，最大 61.79 ms，其余移动在阻塞后合并，统计存在幸存样本偏差；修复后 15/15 次，最大 0.26 ms。该测试证明锁阻塞路径隔离有效，不是实际运行中统计锁会固定持有 180 ms 的证据。

原始结果：`results/input-load-before.json`、`results/input-load-after.json`。公共 UDP 异常恢复和输入生命周期回归也已通过。

## 真实鼠标闭环测试

专用测试目标只在收到 `WM_MOUSEMOVE` 且 `GetCursorPos` 确认实际鼠标坐标后绘制唯一位置标记。主控通过生产 `RemoteInputClient` 发送移动，从返回解码帧识别标记，将其 PTS 对应至 `ConfirmedVideoView.Presented`，计时起止均使用主控本机时钟。首次标记不可见时直接失败，不提前移动鼠标。最多 24 个位置，不点击、不输入文字，目标退出恢复鼠标位置。

被控端启动目标：

```powershell
InputVisualLatency.exe --mouse-target --state target.json --motion false
```

`--motion true` 使用大面积动态背景。将目标生成的状态文件复制至主控，随后运行：

```powershell
InputVisualLatency.exe --config codec-config.json --target-state target.json --report mouse-static.json --host <被控地址> --port <固定端口> --mouse true --preset h264_fast --bitrate 5000 --count 24 --interval 170
```

口令通过 `FRD_TEST_TOKEN` 环境变量提供，不写报告。测试需要两端普通交互桌面，并独占 FRD 主控会话。分别比较静态与动态背景、相同预设下的 1/5/20 Mbps 上限，并查看实际发送带宽、平均/P95/P99、失败样本和阶段数据。码率上限不等于实际带宽。

该工具从生成的输入事件开始计时，包含真实远端鼠标执行及返回画面，但不包含正式主控 UI 的输入采集队列；不能将它标为物理鼠标到显示器发光的测量。

## alipc 双机结果

已实际执行 Windows 鼠标移动，目标通过 `WM_MOUSEMOVE` 和 `GetCursorPos` 确认坐标后绘制位置编号。测试没有点击或文字输入，结束时目标恢复鼠标位置并关闭。

| 场景 | 编码上限 | 完整闭环平均 | 本组 P95/P99/最大 | 样本 |
| --- | --- | --- | --- | --- |
| 修复后静态 | 5 Mbps | 76.68 ms | 91.25 ms | 12 |
| 修复后动态 | 1 Mbps | 85.93 ms | 146.49 ms | 12 |
| 修复后动态首组 | 5 Mbps | 87.94 ms | 126.84 ms | 12 |
| 修复后动态复测 | 5 Mbps | 109.07 ms | 163.55 ms | 12 |
| 修复前被控端动态对照 | 5 Mbps | 104.00 ms | 129.17 ms | 12 |

每组样本很少，P95/P99 与最大值相同，不能据此证明尾延迟分布。动态 1 Mbps 实际发送均值约 0.96 Mbps；5 Mbps 两组约 3.50/3.02 Mbps。后三组带呈现延后计数的测试中，计数均为 0。

可选 `--target-events <共享目录中的目标状态文件.events.jsonl>` 在每次完整计时结束后读取目标诊断。远端时钟用现有 ClockEstimate 校准，只用于分层归因；完整闭环起止仍是主控同一时钟。修复后动态鼠标到位估计平均 10.46～21.53 ms，时钟采样不确定度约 ±3～4 ms。TargetMessageMs 在鼠标模式下为 null，发送完成不称为远端确认。

原始报告：`results/mouse-static-5c.json`、`results/mouse-motion-observed-1.json`、`results/mouse-motion-visible-5.json`、`results/mouse-motion-observed-5.json`、`results/mouse-before-motion-observed-5.json`。

早期动态测试的 220 ms 左右结果包含测量缺陷：动态背景重绘反复擦除确认标记。已改为背景与标记分区更新。另有已解码但较晚取得呈现确认的长尾；测试预览随后设为置顶，并增加 DeferredPresentations 计数。没有计数的早期结果不能证明全部长尾都是窗口遮挡，亦不能用于宣称修复收益。

**结论：统计锁阻塞输入的缺陷已定向复现并修复；正常局域网闭环结果有波动，尚未证明整体鼠标体验显著改善，不能声称用户现场问题已经完全解决。** 本轮没有经过 ArdUi/ARD/FRP 受限公网转发层，也未测物理鼠标采集和显示扫描输出。保持同端口约定，不通过恢复动态端口规避问题。
