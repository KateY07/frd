# 2880×1800 捕获后缩到 1440×900 的短测

本机 Intel Arc 140T，真实 DXGI 桌面，受控全画面动态，30 FPS、2 Mbps H.264 上限。主指标从捕获调用开始到完整编码包返回；不含新画面等待、UDP、解码和渲染。每条路径预热 5 帧、计时 30 帧。路径顺序执行，画面不逐像素相同，不能把差额全归因于分辨率。

| 路径 | 捕获/预处理均值 | 编码均值 | 合计均值 / P95 | 输出码率 |
|---|---:|---:|---:|---:|
| 原始 2880×1800，CPU 映射→x264rgb | 2.52 ms | 6.22 ms | 8.74 / 10.86 ms | 1.42 Mbps |
| GPU 缩小→1440×900 BGRA 回读→CPU x264 | 3.00 ms | 3.42 ms | 6.42 / 9.42 ms | 0.98 Mbps |
| GPU 缩小并取 8 位灰度→回读→CPU x264 | 2.53 ms | 2.27 ms | 4.80 / 6.93 ms | 1.12 Mbps |
| 原始 2880×1800，GPU 转 NV12→QSV | 无 CPU 像素回读 | 计入总时长 | 17.22 / 18.59 ms | 2.00 Mbps |
| GPU 缩小并转 NV12→QSV，纹理直通 | 无 CPU 像素回读 | 计入总时长 | 9.76 / 10.62 ms | 2.00 Mbps |

两条 QSV 路径同轮实测，半尺寸减少 7.46 ms，约 43%；独立复核的原尺寸为 16.79 / 17.11 ms，半尺寸为 10.15 / 11.97 ms，均 35/35 帧解码且有 35 种解码画面。此前在另一组参数下原尺寸 QSV 曾测约 10.70 ms，因此不能把这里的节省视为所有码率、画面和驱动条件下的固定收益。半尺寸路径属于真正的 GPU 缩放、转色、硬编，不把纹理回读到 CPU；编码后的码流仍回到 CPU 才能通过 UDP 发送。QSV 编码调用包含前序 GPU 工作、驱动同步和出包，不能按 API 名字拆成“纯硬编耗时”。此隔离测试使用现有 QSV loader 生命周期兼容绕过，不等于长期运行的生产后端已就绪。

CPU 三条路径也都 35/35 帧解码，半尺寸 BGRA 与灰度均有持续画面变化。相对原始 x264rgb，半尺寸彩色总时长少 2.32 ms（约 27%），灰度少 3.94 ms（约 45%）；编码器颜色格式及输出画质同时变了，不能视作单纯缩放增益。原始 20.74 MB BGRA 像素变为半尺寸 5.18 MB BGRA 或 1.30 MB Gray8。压缩后的 H.264 字节数并不按原始像素比例下降，实际取决于画面、码率控制和画质。

RGB332 是真正 1 字节彩色（红 3、绿 3、蓝 2 位），但这组相近颜色的整屏动态被量化成同一种像素模式，解码画面也静止；它的 5.38 ms 与约 0.01 Mbps 是**无效成绩**，不能当作可用远程桌面路径。RG8 是 2 字节每像素，且只保留两个通道。若要低内存占用而仍保留常规色彩与硬编兼容性，半尺寸 NV12 是目前已验证的候选：平均 1.5 字节每像素，且在本次 QSV 路径中无需 CPU 原始像素回读。
